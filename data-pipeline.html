간단한 데이터 파이프라인

한국어 번역본원문 기준 2026.09.21Tasty Bytes
교육 참석자용 · 외부 공유 및 재배포 금지

개요#

이 시나리오에서는 Snowflake에서 간단한 자동화 데이터 파이프라인을 구축하는 방법을 배웁니다. 먼저 외부 Stage에서 원시 반정형 데이터를 수집한 다음, Snowflake의 강력한 Dynamic Table을 사용하여 데이터를 변환하고 보강합니다. 이를 통해 새 데이터가 도착하면 자동으로 최신 상태를 유지하는 파이프라인을 만듭니다.

학습할 내용#

  • 외부 S3 Stage에서 데이터를 수집하는 방법.
  • 반정형 VARIANT 데이터를 쿼리하고 변환하는 방법.
  • FLATTEN 함수로 배열을 파싱하는 방법.
  • Dynamic Table을 생성하고 연결하는 방법.
  • ELT 파이프라인이 새 데이터를 자동으로 처리하는 방식.
  • 방향성 비순환 그래프(DAG)로 파이프라인을 시각화하는 방법.

구현할 내용#

  • 데이터 수집을 위한 외부 Stage.
  • 원시 데이터를 위한 스테이징 테이블.
  • Dynamic Table 세 개를 연결한 다단계 데이터 파이프라인.

SQL을 가져와 SQL 파일에 붙여넣으세요.#

Snowflake에서 따라 하려면 이 파일의 SQL을 복사하여 새 SQL 파일에 붙여넣으세요. SQL 파일의 끝까지 진행했다면 16단계 - Snowflake Cortex AI로 건너뛸 수 있습니다.

외부 Stage에서 데이터 수집하기#

개요#

현재 원시 메뉴 데이터는 Amazon S3 버킷에 CSV 파일로 저장되어 있습니다. 파이프라인을 시작하려면 먼저 이 데이터를 Snowflake로 수집해야 합니다. S3 버킷을 가리키는 Stage를 생성한 다음 COPY 명령으로 데이터를 스테이징 테이블에 로드하겠습니다.

1단계 - 컨텍스트 설정하기#

먼저 올바른 데이터베이스, 역할, 웨어하우스를 사용하도록 세션 컨텍스트를 설정하겠습니다. SQL 파일의 처음 몇 개 쿼리를 실행합니다.

SQL
ALTER SESSION SET query_tag = '{"origin":"sf_sit-is","name":"tb_zts","version":{"major":1, "minor":1},"attributes":{"is_quickstart":1, "source":"tastybytes", "vignette": "data_pipeline"}}';

USE DATABASE tb_101;
USE ROLE tb_data_engineer;
USE WAREHOUSE tb_de_wh;

2단계 - Stage 및 스테이징 테이블 생성하기#

Stage는 데이터 파일이 저장된 외부 위치를 지정하는 Snowflake 오브젝트입니다. 공개 S3 버킷을 가리키는 Stage를 생성하겠습니다. 그런 다음 이 원시 데이터를 저장할 테이블을 생성합니다.

SQL
-- 메뉴 데이터용 Stage를 생성합니다
CREATE OR REPLACE STAGE raw_pos.menu_stage
COMMENT = 'Stage for menu data'
URL = 's3://sfquickstarts/frostbyte_tastybytes/raw_pos/menu/'
FILE_FORMAT = public.csv_ff;

CREATE OR REPLACE TABLE raw_pos.menu_staging
(
    menu_id NUMBER(19,0),
    menu_type_id NUMBER(38,0),
    menu_type VARCHAR(16777216),
    truck_brand_name VARCHAR(16777216),
    menu_item_id NUMBER(38,0),
    menu_item_name VARCHAR(16777216),
    item_category VARCHAR(16777216),
    item_subcategory VARCHAR(16777216),
    cost_of_goods_usd NUMBER(38,4),
    sale_price_usd NUMBER(38,4),
    menu_item_health_metrics_obj VARIANT
);

3단계 - 스테이징 테이블로 데이터 복사하기#

Stage와 테이블을 준비했으니 menu_staging 테이블에 Stage의 데이터를 COPY INTO 명령으로 로드하겠습니다.

SQL
COPY INTO raw_pos.menu_staging
FROM @raw_pos.menu_stage;

COPY INTO TABLE: 이 강력한 명령은 Stage에 있는 파일의 데이터를 Snowflake 테이블로 로드합니다. 대량 데이터를 수집하는 기본적인 방법입니다.

반정형 데이터#

개요#

Snowflake는 기본 제공 VARIANT 데이터 타입으로 JSON과 같은 반정형 데이터를 효과적으로 처리합니다. 수집한 컬럼 중 하나인 menu_item_health_metrics_obj에는 JSON이 포함되어 있습니다. 이를 쿼리하는 방법을 살펴보겠습니다.

1단계 - VARIANT 데이터 쿼리하기#

원시 JSON을 살펴보겠습니다. 중첩된 오브젝트와 배열이 포함되어 있다는 점에 주목하세요.

SQL
SELECT menu_item_health_metrics_obj FROM raw_pos.menu_staging;

특수 구문을 사용하여 JSON 구조를 탐색할 수 있습니다. 콜론(:)은 이름으로 키에 액세스하고, 대괄호([])는 인덱스로 배열 요소에 액세스합니다. CAST 함수나 이중 콜론 축약 구문(::)을 사용하여 결과를 명시적인 데이터 타입으로 변환할 수도 있습니다.

SQL
SELECT
    menu_item_name,
    CAST(menu_item_health_metrics_obj:menu_item_id AS INTEGER) AS menu_item_id, -- 'AS'를 사용하여 타입을 변환합니다
    menu_item_health_metrics_obj:menu_item_health_metrics[0]:ingredients::ARRAY AS ingredients -- 이중 콜론(::) 구문을 사용하여 타입을 변환합니다
FROM raw_pos.menu_staging;

2단계 - FLATTEN으로 배열 파싱하기#

FLATTEN 함수는 배열의 중첩을 해제하는 강력한 도구입니다. 배열의 각 요소에 대해 새 로우를 생성합니다. 이 함수를 사용하여 모든 메뉴 항목의 재료 목록을 만들어 보겠습니다.

SQL
SELECT
    i.value::STRING AS ingredient_name,
    m.menu_item_health_metrics_obj:menu_item_id::INTEGER AS menu_item_id
FROM
    raw_pos.menu_staging m,
    LATERAL FLATTEN(INPUT => m.menu_item_health_metrics_obj:menu_item_health_metrics[0]:ingredients::ARRAY) i;

반정형 데이터 타입: Snowflake의 VARIANT, OBJECT, ARRAY 타입을 사용하면 엄격한 스키마를 미리 정의하지 않고도 반정형 데이터를 직접 저장하고 쿼리할 수 있습니다.

Dynamic Table#

개요#

프랜차이즈에서는 새로운 메뉴 항목을 계속 추가하고 있습니다. 이러한 새 데이터를 자동으로 처리할 방법이 필요합니다. 이를 위해 Dynamic Table을 사용할 수 있습니다. Dynamic Table은 쿼리 결과를 선언적으로 정의하고 새로 고침은 Snowflake에 맡겨 데이터 변환 파이프라인을 간소화하도록 설계된 강력한 도구입니다.

1단계 - 첫 번째 Dynamic Table 생성하기#

먼저 스테이징 테이블에서 중복을 제거한 전체 재료 목록을 추출하는 Dynamic Table을 생성하겠습니다. LAG를 '1 minute'으로 설정하면 이 테이블의 데이터가 소스 데이터보다 뒤처질 수 있는 최대 시간을 Snowflake에 지정할 수 있습니다.

SQL
CREATE OR REPLACE DYNAMIC TABLE harmonized.ingredient
    LAG = '1 minute'
    WAREHOUSE = 'TB_DE_WH'
AS
    SELECT
    ingredient_name,
    menu_ids
FROM (
    SELECT DISTINCT
        i.value::STRING AS ingredient_name, 
        ARRAY_AGG(m.menu_item_id) AS menu_ids
    FROM
        raw_pos.menu_staging m,
        LATERAL FLATTEN(INPUT => menu_item_health_metrics_obj:menu_item_health_metrics[0]:ingredients::ARRAY) i
    GROUP BY i.value::STRING
);

Dynamic Table: Dynamic Table은 기반 소스 데이터가 변경되면 자동으로 새로 고쳐집니다. 따라서 수동 개입이나 복잡한 스케줄링 없이 ELT 파이프라인을 간소화하고 데이터 최신성을 유지할 수 있습니다.

2단계 - 자동 새로 고침 테스트하기#

자동화가 어떻게 동작하는지 살펴보겠습니다. 푸드 트럭 한 대에서 새로운 재료인 프랑스식 바게트와 절인 무가 들어가는 반미 샌드위치를 추가했습니다. 이 새 메뉴 항목을 스테이징 테이블에 삽입해 보겠습니다.

SQL
INSERT INTO raw_pos.menu_staging 
SELECT 
    10101, 15, 'Sandwiches', 'Better Off Bread', 157, 'Banh Mi', 'Main', 'Cold Option', 9.0, 12.0,
    PARSE_JSON('{"menu_item_health_metrics": [{"ingredients": ["French Baguette","Mayonnaise","Pickled Daikon","Cucumber","Pork Belly"],"is_dairy_free_flag": "N","is_gluten_free_flag": "N","is_healthy_flag": "Y","is_nut_free_flag": "Y"}],"menu_item_id": 157}');

이제 harmonized.ingredient 테이블을 쿼리합니다. 1분 이내에 새 재료가 자동으로 나타나는 것을 확인할 수 있습니다.

SQL
-- 최대 1분 동안 기다린 후 이 쿼리를 다시 실행해야 할 수 있습니다
SELECT * FROM harmonized.ingredient 
WHERE ingredient_name IN ('French Baguette', 'Pickled Daikon');

파이프라인 확장하기#

개요#

이제 다른 Dynamic Table에서 데이터를 읽는 Dynamic Table을 추가로 생성하여 여러 단계의 파이프라인을 구축할 수 있습니다. 이렇게 하면 소스에서 최종 출력까지 업데이트가 자동으로 전달되는 체인, 즉 방향성 비순환 그래프(DAG)가 만들어집니다.

1단계 - 룩업 테이블 생성하기#

재료를 해당 재료가 사용되는 메뉴 항목에 매핑하는 룩업 테이블을 생성해 보겠습니다. 이 Dynamic Table은 harmonized.ingredient Dynamic Table에서 데이터를 읽습니다.

SQL
CREATE OR REPLACE DYNAMIC TABLE harmonized.ingredient_to_menu_lookup
    LAG = '1 minute'
    WAREHOUSE = 'TB_DE_WH'   
AS
SELECT
    i.ingredient_name,
    m.menu_item_health_metrics_obj:menu_item_id::INTEGER AS menu_item_id
FROM
    raw_pos.menu_staging m,
    LATERAL FLATTEN(INPUT => m.menu_item_health_metrics_obj:menu_item_health_metrics[0]:ingredients) f
JOIN harmonized.ingredient i ON f.value::STRING = i.ingredient_name;

2단계 - 트랜잭션 데이터 추가하기#

주문 테이블에 레코드를 삽입하여 반미 샌드위치 두 개를 주문하는 상황을 시뮬레이션해 보겠습니다.

SQL
INSERT INTO raw_pos.order_header
SELECT 
    459520441, 15, 1030, 101565, null, 200322900,
    TO_TIMESTAMP_NTZ('08:00:00', 'hh:mi:ss'),
    TO_TIMESTAMP_NTZ('14:00:00', 'hh:mi:ss'),
    null, TO_TIMESTAMP_NTZ('2022-01-27 08:21:08.000'),
    null, 'USD', 14.00, null, null, 14.00;
    
INSERT INTO raw_pos.order_detail
SELECT
    904745311, 459520441, 157, null, 0, 2, 14.00, 28.00, null;

3단계 - 파이프라인의 최종 테이블 생성하기#

마지막으로 최종 Dynamic Table을 생성해 보겠습니다. 이 테이블은 주문 데이터와 재료 룩업 테이블을 조인하여 트럭별 월간 재료 사용량 요약을 생성합니다. 이 테이블은 다른 Dynamic Table에 의존하며 파이프라인을 완성합니다.

SQL
CREATE OR REPLACE DYNAMIC TABLE harmonized.ingredient_usage_by_truck 
    LAG = '2 minute'
    WAREHOUSE = 'TB_DE_WH'  
    AS 
    SELECT
        oh.truck_id,
        EXTRACT(YEAR FROM oh.order_ts) AS order_year,
        MONTH(oh.order_ts) AS order_month,
        i.ingredient_name,
        SUM(od.quantity) AS total_ingredients_used
    FROM
        raw_pos.order_detail od
        JOIN raw_pos.order_header oh ON od.order_id = oh.order_id
        JOIN harmonized.ingredient_to_menu_lookup iml ON od.menu_item_id = iml.menu_item_id
        JOIN harmonized.ingredient i ON iml.ingredient_name = i.ingredient_name
        JOIN raw_pos.location l ON l.location_id = oh.location_id
    WHERE l.country = 'United States'
    GROUP BY
        oh.truck_id,
        order_year,
        order_month,
        i.ingredient_name
    ORDER BY
        oh.truck_id,
        total_ingredients_used DESC;

4단계 - 최종 출력 쿼리하기#

이제 파이프라인의 최종 테이블을 쿼리해 보겠습니다. 새로 고침이 완료될 때까지 몇 분 기다리면 이전 단계에서 삽입한 주문의 반미 두 개에 대한 재료 사용량을 확인할 수 있습니다. 전체 파이프라인이 자동으로 업데이트되었습니다.

SQL
-- 최대 2분 동안 기다린 후 이 쿼리를 다시 실행해야 할 수 있습니다
SELECT
    truck_id,
    ingredient_name,
    SUM(total_ingredients_used) AS total_ingredients_used
FROM
    harmonized.ingredient_usage_by_truck
WHERE
    order_month = 1
    AND truck_id = 15
GROUP BY truck_id, ingredient_name
ORDER BY total_ingredients_used DESC;

파이프라인 시각화하기#

개요#

마지막으로 파이프라인의 방향성 비순환 그래프, 즉 DAG를 시각화해 보겠습니다. DAG는 데이터가 테이블을 통해 흐르는 방식을 보여 주며, 파이프라인의 상태와 지연을 모니터링하는 데 사용할 수 있습니다.

1단계 - Graph 뷰에 접근하기#

Snowsight에서 DAG에 접근하려면 다음 단계를 따릅니다:

  1. Data » Database로 이동합니다.
  2. 데이터베이스 오브젝트 탐색기에서 TB_101 데이터베이스와 HARMONIZED 스키마를 확장합니다.
  3. Dynamic Tables를 클릭합니다.
  4. 생성한 Dynamic Table 중 하나(예: INGREDIENT_USAGE_BY_TRUCK)를 선택합니다.
  5. 메인 창에서 Graph 탭을 클릭합니다.

이제 기본 테이블의 데이터가 Dynamic Table로 흐르는 방식을 보여 주는 파이프라인 시각화가 표시됩니다.
